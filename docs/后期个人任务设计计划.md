# 后期个人任务设计计划

## 1. 目标

当前 `奇遇` 任务页在 `@御寒宝物` 之后缺少完整个人任务推进，导致雪域、火龙、狐月后期内容更像功能入口和副本入口，而不是一条有背景、有目标、有回报的后期主线。

本计划设计一条新的个人任务线，顺序固定为：

1. 雪域地图板块
2. 火龙地图板块
3. 狐月地图板块

任务入口依托现有三组 NPC：

- 雪域：银杏村穆家店看板娘、盟重城雪域世界、雪域老人
- 火龙：比奇城火龙将军、火龙勇士、云隐宗师、毒蛇山谷王大娘
- 狐月：白日门阿狸、比奇城海边老兵、狐月岛阿狸、狐月长老

计划只设计个人任务线，不改 `G0` 世界阶段逻辑。

## 2. 设计原则

- 使用新的连续个人任务标志位，避免占用现有 `[47]`、`[48]`、`[250]`、`[251]`、`[255]`、`[256]`。
- 保留原有功能入口，不破坏雪域镜像、火龙勇士、狐月上船、狐火突破等现有玩法。
- 任务说明页 `QMission-0.txt` 只做导航和进度展示，实际推进仍由 NPC 和击杀触发处理。
- 击杀型任务必须使用完整怪物名，并在击杀触发里检查任务状态位。
- 任务链可以长，但每一步都要有明确的 NPC、条件、回写和失败提示。
- NPC 不只发功能按钮，也承担世界观叙事：他们知道局部真相、各有私心或遗憾，玩家通过跑图把这些信息拼起来。

## 4. 任务总线剧情

世界观核心建议：

雪域、火龙、狐月不是三个孤立副本，而是同一场旧战争的三段余波。

- 二十年前，雪域裂隙打开，北方寒潮南侵。银杏村看板娘的父亲曾是边防将领，带兵北上后失踪。
- 火龙军团曾奉命深入地下寻找雪域寒潮的源头，却发现火龙洞穴并非天然地脉，而是古代封印的反噬。
- 狐月岛保存着上古三仙封印妖兽的阵眼。雪域的寒、火龙的焰、狐月的灵，其实都是封印松动后的三种外泄力量。
- 玩家先救一个家族的遗憾，再收拾一支军团的败局，最后触碰上古封印真相。

这条线的调性建议是“老传奇 NPC 的碎片化叙事”：每个 NPC 不讲全貌，只说自己知道的部分。玩家一路跑下来，才发现这是同一条后期主线。

## 5. 第一章：雪域地图板块

### 5.1 起点：穆家店看板娘

涉及文件：

- `Mir200/Envir/Market_def/银杏村/穆家店-0.txt`
- `Mir200/Envir/Market_def/QMission-0.txt`

设计：

- 在现有 `雪域奇遇` 对话基础上升级为后期奇遇总线入口。
- 如果 `[48]` 已完成，玩家可继续追问父亲被困原因。
- 看板娘提到父亲虽然活着，但灵魂仍被雪域魂器拴住，必须找回魂器残片。

条件：

- 已完成现有御寒宝物：`CHECK [48] 1`
- 后期地图已开放：可按原入口的 `G0` 判断，不在任务状态里重复定义

状态推进：

- 设置 `[500] 1`
- 设置 `[501] 1`

世界观作用：

- 把“找父亲”从一次报信扩展成“解除雪域军魂桎梏”。
- 看板娘从仓库 NPC 变成雪域章节的情感入口。

### 5.2 进入雪域：盟重城雪域世界

涉及文件：

- `Mir200/Envir/Market_def/盟重城/雪域世界-3.txt`

设计：

- 雪人不再只是传送机器。
- 当玩家持有 `[501]` 时，雪人显示“封印痕迹正在回应你”，引导玩家进入雪域镜像或野外。
- 不改变现有野图、单人、组队副本消耗。

完成条件：

- 玩家进入雪域任意线路后，任务继续由雪域老人承接。

状态推进：

- 不强制在传送时推进，避免玩家付费进图但没完成内容。

世界观作用：

- 雪人是国师留下的封印锚点，不只是收费入口。

### 5.3 雪域老人：魂器真相

涉及文件：

- `Mir200/Envir/Market_def/其它区域/雪域_雪域老人-YXSD.txt`
- `Mir200/Envir/Market_def/雪域_雪域老人.txt`

设计：

- 雪域老人确认自己被雪域魔王的魂器束缚。
- 要求玩家先证明能在雪域活下来：击杀一批雪域怪并带回冰核。

完成条件建议：

- 击杀雪域普通怪 30 只，计入 `U40`。
- 提交 `冰核` 3 个。
- 再击杀 `雪域魔王[BOSS]`。

状态推进：

- 见到老人：`[502] 1`
- 普通怪计数完成后，可交 `冰核` 3 个
- 击杀 `雪域魔王[BOSS]`：`[503] 1`
- 交付后：`[504] 1`

奖励建议：

- `CREDITPOINT + 80`
- `CHANGEEXP + 1000000`
- `GIVE 火龙凭证 1`
- `GIVESTATEITEM 避寒神丹 2`
- 可给称号：`雪域寻魂`

世界观作用：

- 雪域魔王不是单纯 Boss，而是战死军魂不能归乡的源头。
- 冰核被解释为魂器外壳剥落的寒晶。

## 9. DB 协同设计

`Mud2/DB/GEEM2.db` 是 SQLite 数据库，当前可静态读取到三张核心表：`StdItems`、`Monster`、`Magic`。本计划只需要协同 `StdItems`，用于脚本中的 `GIVE`、`GIVESTATEITEM`、`CHECKITEM`、`TAKE`、`GIVEFENGHAO`、`CHECKFENGHAO`。

项目规则把 `.db` 归为数据库文件，实施前建议先审批 DB 清单，再由你或指定工具入库。脚本实现时必须保证：任何新物品或新称号在 `StdItems` 中存在后，才能写入 `GIVE` / `GIVEFENGHAO` 发放逻辑。

### 9.3 DB 入库后的文本协同

新增 `StdItems` 后，还要同步以下文本配置，避免玩家看到空说明或道具规则不一致：

- `Mir200/Envir/ItemDescList.txt`：补 `雪域魂器残片`、`狐月引路符`、`雪域寻魂`、`火龙余烬`、`狐月问道` 的说明。
- `Mir200/Envir/FilterItemList.txt`：按任务物品和称号现有规则补自动拾取 / 过滤配置；`狐月引路符` 和 `雪域魂器残片` 建议按 `火龙凭证`、`冰核` 一类任务物品处理。
- `Mir200/Envir/ItemRuleList.txt`：如果希望 `雪域魂器残片`、`狐月引路符` 禁止交易、禁止丢弃或丢弃消失，应仿照 `冰核`、`装备转移宝盒` 补规则；若允许交易，则不强制新增。

### 9.4 DB 缺失时的脚本策略

审批前不建议在脚本里直接发放缺失 DB 项，否则玩家完成任务时可能拿不到道具或出现异常提示。临时方案如下：

- `狐月引路符` 未入库前：火龙收束奖励改为 `GIVE 狐火 10`，白日门阿狸用 `CHECKITEM 狐火 10` 作为临时引路凭据。
- `雪域魂器残片` 未入库前：雪域章节只用状态位 `[504]` 表示带回残片，不发实物。
- `雪域寻魂`、`火龙余烬`、`狐月问道` 未入库前：先不写 `GIVEFENGHAO`，用 `SENDMSG` 提示“称号待开放”，避免脚本调用不存在称号。

## 11. 后续实现注意点

- Mir200 脚本文本按 ANSI/GBK 读取和写回，保持原编码和换行风格。
- 新增标签名建议加前缀，例如 `@后期奇遇_雪域魂器`，减少和现有标签冲突。
- 击杀触发必须检查任务状态位，避免玩家提前击杀 Boss 导致任务跳步。
- `狐月天珠[BOSS]`、`雪域魔王[BOSS]`、`金杖蜘蛛[狂暴]` 这类怪名必须完整匹配。
- `RefreshMissPage 奇遇` 应在每次关键推进后调用。
- 奖励发放前检查背包空格，失败时不写完成状态。
- 新增物品或称号先入 `StdItems`，再写脚本发放；脚本里不要先引用 DB 中不存在的名字。
- 现有副本标志 `[250]`、`[251]` 不参与个人任务完成判断，只作为副本存在状态。
- 现有狐月通行标志 `[255]` 可以被任务读取，但不要重定义它的含义。

## 12. 静态验证计划

审批通过并实现后，建议做这些静态检查：

1. 搜索新增状态位 `[500]` 到 `[526]`，确认每个状态位只有预期用途。
2. 搜索新增标签，确认所有跳转目标都存在。
3. 搜索 `RefreshMissPage 奇遇`，确认关键推进节点都会刷新任务页。
4. 搜索 `CheckKillMonName`，确认后期任务 Boss 名完整匹配。
5. 搜索 `QMission-0.txt` 中的任务标签，确认每个任务说明标签都存在。
6. 检查所有奖励发放前是否有 `CHECKBAGSIZE` 或明确无需背包空间。
7. 静态确认没有修改 `G0` 世界阶段推进逻辑。
8. 静态查询 `Mud2/DB/GEEM2.db` 的 `StdItems`，确认 `GIVE`、`GIVESTATEITEM`、`GIVEFENGHAO` 引用的新增名称都存在。
9. 搜索 `ItemDescList.txt`、`FilterItemList.txt`、`ItemRuleList.txt`，确认新增 DB 项的说明、拾取过滤和道具规则已同步。
