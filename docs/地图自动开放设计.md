# 地图自动开放设计

## 目标

当前版本通过手动调整全局变量 `G0` 控制地图开放，维护成本高，也不利于开区节奏自然推进。本设计把 `G0` 定义为“世界开放阶段”，由玩家击杀指定区域 Boss 自动推进。

设计原则：

- 默认只开放比奇省及比奇周边初始地图。
- 每个阶段由一个明确 Boss 首杀触发。
- 首杀后全服公告，并把 `G0` 推进到下一阶段。
- 后续传送 NPC、地图入口、挂机/随机传送逻辑只读取 `G0`，不再人工改阶段。
- 所有入口必须采用同一套“目标地图阶段检查”；本文只设计，不修改现有脚本。

## 已确认的现有机制

配置事实：

- `Mir200/Envir/MapQuest_def/QManage.txt` 已经读取 `G0`，在登录/功能初始化处按 `G0=0/1/2/3` 和 `G0>4` 显示不同按钮。
- `Mir200/Envir/Market_def/QFunction-0.txt` 的 `[@OnKillMob]` 会调用 `系统功能\老登辅助\杀怪触发.txt`。
- `Mir200/Envir/QuestDiary/系统功能/老登辅助/杀怪触发.txt` 已经用 `CheckKillMonName` 处理尸王、祖玛教主、魔龙教主等击杀触发。
- 本地知识库手册 `knowledge_base/chapters/696-杀死怪物时触发-杀怪触发.md` 明确：`[@OnKillMob]` 必须配合地图参数 `ONKILLMON` 才会生效。
- `[@KillMon]` 不需要地图参数 `ONKILLMON`；设计中不能用 `[@KillMon]` 的触发条件反推 `[@OnKillMob]` 的地图配置。
- `MapInfo.txt` 中部分关键 Boss 地图已经带有 `ONKILLMON` 或 `KILLMON`，例如祖玛教主之家、赤月魔穴、封魔殿、魔龙血域、魔龙殿、雪域、狐月、雷炎等；实际实现首杀触发时，以 `ONKILLMON` 为准，并逐张地图静态核对。

推论：

- 最低风险实现方式是继续利用 `QFunction-0.txt -> 杀怪触发.txt` 这条现有入口。
- 自动开放逻辑应追加到 `杀怪触发.txt`，用完整怪物名匹配、`EQUAL <$MAP> 地图编号` 和 `EQUAL G0 当前阶段` 防止误触发和重复推进。
- 对当前没有 `ONKILLMON` 的早期地图，若要让 Boss 首杀触发阶段推进，需要在对应地图配置上补 `ONKILLMON`。
- Boss 名称必须与 `MonGen.txt` 中的实际名称完整一致。带数字、括号或其他后缀的名称不能自动视为基础名称的同一个 Boss。

## 开放控制建议

### 阶段变量

推荐继续使用 `G0`，因为当前工程已经用它控制开区 UI。语义约定如下：

- `G0=0`：比奇初始
- `G0=1`：沃玛森林
- `G0=2`：毒蛇山谷与矿区
- `G0=3`：盟重省
- `G0=4`：白日门与赤月
- `G0=5`：封魔谷
- `G0=6`：苍月岛
- `G0=7`：幻境
- `G0=8`：魔龙城
- `G0=9`：雷炎
- `G0=10`：雪域
- `G0=11`：火龙
- `G0=12`：狐月

如果担心 `G0` 影响现有按钮逻辑，可以新增一个更独立的全局变量，例如 `G20` 作为世界阶段，再让 `G0` 继续服务旧 UI。但这会增加迁移工作量。

阶段变量还必须满足：

- 初始化值只能是已定义的阶段值；异常值不能默认放行所有地图。
- 推进条件必须同时校验完整怪物名、当前地图和当前 `G0`，并且只执行 `G0` 加一。
- 阶段推进成功后才发送全服公告；重复击杀、重复脚本调用和并发触发不能重复推进或重复公告。
- 阶段表必须覆盖所有可进入地图，而不是只登记 Boss 地图。

### 击杀触发入口

推荐追加一个新脚本：

- `Mir200/Envir/QuestDiary/系统功能/地图开放.txt`

然后在现有 `杀怪触发.txt` 最后追加一行调用：

- `#CALL [系统功能\地图开放.txt] @地图开放_杀怪触发`

这样做的好处：

- 不把阶段逻辑塞进已有任务脚本里。
- 后续调整阶段表只改一个文件。
- 不影响尸王、祖玛教主、魔龙教主现有任务状态位。

### 入口拦截与防偷渡矩阵

阶段推进只是第一步。真正限制玩家活动，需要所有进入方式都读同一张“目标地图 -> 开放阶段”表。不能只在 NPC 按钮上加判断，否则玩家仍可能通过地图连接、召回、道具、活动或重连进入未开放区域。

| 入口类别 | 静态排查对象 | 必须覆盖的风险 |
| --- | --- | --- |
| 地图自然连接 | `MapInfo.txt` 中的坐标传送、地图门、地图连接 | 走路、踩点、地图门或坐标触发直接进入高级地图 |
| NPC / 商人传送 | `MerChant.txt`、`Npc_def/`、`Market_def/` | `MAPMOVE`、`MAP`、`MAPS`、`GROUPMAPMOVE` 等直接传送 |
| 功能与快捷传送 | `QManage.txt`、辅助脚本、快捷菜单 | UI 隐藏了入口但脚本标签仍可被调用 |
| 召回与换图 | `RECALL`、`RECALLMAP`、`ExchangeMap`、组队/行会/夫妻/师徒/英雄召回 | 高级地图玩家把低阶段玩家带入，或召回动作绕过 NPC 检查 |
| 道具传送 | 回城卷、随机传送、地牢逃脱、行会回城、传送符及礼包/绑定版本 | 物品脚本直接指定高级地图或随机落点落入高级区域 |
| 动态地图与副本 | `AddMirrorMap`、`DelMirrorMap`、`MONGEN`、`MONGENEX`、`CreateNPC` | 副本入口、镜像地图或动态 NPC 未登记阶段 |
| 活动 / 任务 / 机器人 | 活动脚本、任务脚本、`Robot_def/`、自动执行脚本 | 定时活动、任务完成、机器人逻辑直接 `map` / `MAPMOVE` |
| 重连、死亡、复活 | 登录回地图、死亡回城、复活点、异常断线恢复 | 玩家重连或复活时回到未开放地图 |
| 随机移动 | 随机传送、地图内随机点、地图事件 | 只检查目标地图名称但未检查随机坐标和落点 |
| 管理命令 | GM / 管理员传送和脚本命令 | 普通玩家借助可调用命令越境；管理员例外必须显式判断 |

推荐实现方式：

- 新增统一地图阶段模块，例如 `Mir200/Envir/QuestDiary/系统功能/地图开放.txt`，集中维护阶段表、完整 Boss 条件、目标地图判断和失败提示。
- 所有脚本在执行传送动作前，传入或明确目标地图，先调用统一检查；不能只依赖调用方界面是否显示。
- 对 `MapInfo.txt` 的自然连接、重连、死亡/复活等无法在传送按钮前统一拦截的路径，还需要在地图进入或换图后的统一纠正点再次校验。
- 未开放目标必须拒绝进入，并把玩家送回最近的已开放安全地图；具体纠正命令和触发标签先查本地手册，不在设计阶段臆造。
- 阶段推进后，已经正常进入的玩家不应被错误清退；只有检测到目标地图阶段高于当前 `G0` 且不属于管理员显式例外时，才按统一纠正策略处理。
- 新增地图、活动、副本、道具或传送脚本时，必须同时补充阶段表和入口检查，否则视为未完成。

## 首杀公告文案建议

公告应明确“谁击杀、击杀了什么、开放了哪里”：

- `SENDMSG 1 【世界进度】<$USERNAME> 击杀骷髅精灵，沃玛森林区域已经开放！`
- `SENDMSG 1 【世界进度】<$USERNAME> 击杀沃玛教主，毒蛇山谷与矿区已经开放！`
- `SENDMSG 1 【世界进度】<$USERNAME> 击杀祖玛教主，白日门与赤月峡谷已经开放！`

如果需要避免重复公告，必须让每条推进逻辑都带 `EQUAL G0 当前阶段`，推进后立刻 `MOV G0 下一阶段`。

## 风险与实现前核查点

- `[@OnKillMob]` 必须配合 `ONKILLMON`；`[@KillMon]` 不需要 `ONKILLMON`。本设计的 Boss 首杀入口采用前者，因此不能把 `KILLMON` 当作替代条件。
- 早期地图如 `D003`、`D012`、`D2079` 当前未见 `ONKILLMON`，如果选它们作为首杀触发地图，实现时需要改 `MapInfo.txt`。
- 幻境怪物名大量带后缀，例如 `牛魔王8`、`赤月恶魔8`；实现时必须按完整名匹配，不能忽略后缀。
- `G0` 已被 `QManage.txt` 用于按钮显示，阶段数扩展到 `9` 后，`LARGE G0 4` 分支会长期生效，需要确认这是预期行为。
- 所有越境入口都必须纳入静态清单；只靠 `MapInfo.txt`、NPC 或按钮中的单点限制都不完整。

## 静态验证清单

后续真正实现前，应逐项静态核对：

- 每个阶段 Boss 所在地图是否有 `ONKILLMON`。
- 每个阶段 Boss 名是否和 `MonGen.txt` 完全一致。
- 每个 `MAPMOVE`、`MAP`、`MAPS`、`GROUPMAPMOVE` 入口是否有阶段检查。
- 每个 `RECALL`、`RECALLMAP`、`ExchangeMap` 和动态地图入口是否有阶段检查。
- 每个传送道具、活动、任务、机器人、重连、死亡/复活路径是否有阶段检查。
- `MapInfo.txt` 自然连接和地图门是否会把玩家送入未开放地图。
- 目标地图是否都已登记阶段，未知地图是否默认拒绝而不是默认放行。
- `G0` 推进是否只允许从当前阶段到下一阶段，不能跳级。
