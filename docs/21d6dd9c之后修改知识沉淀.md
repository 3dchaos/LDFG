# 21d6dd9c 之后修改知识沉淀

范围：`21d6dd9c309ebdc57f51fabed2414979e85cba4a` 之后到当前 `HEAD` 的全部修改。

这段历史的主线很清楚：围绕“英雄军鼓”把一个特性从最初可用，逐步补成完整生命周期。

## 这次改动做了什么

1. 先修了一个引擎副作用：`LockUpdateAbil` 会卡住月灵移动，所以道士军鼓相关流程把长持锁改成了更保守的写法。
2. 做了英雄军鼓阶段1：英雄 14 号位独立穿戴后，能登录、穿戴、卸下、死亡、定时续期地维持常驻属性。
3. 做了阶段2：补上英雄受击前减伤闭环，把 `@HeroStruckDamage` 接到军鼓逻辑里。
4. 又补了攻击向镜像：把 `@HeroAttackDamage` 接入，让英雄主动打怪时也吃到方向效果。
5. 修了“2 秒后回归”的续期问题：单靠一次 `ChangeHumAbility` 不够，必须有独立定时器续写。
6. 最后继续扩展到新阶段，说明这个模块已经从“单点效果”变成“分阶段能力系统”。

## 可复用经验

### 1. 英雄和玩家必须分域
英雄军鼓不能复用玩家的 `S$` / `N$` 状态，最好单独一套变量域和清理链路。  
这次就是靠 `N$英雄军鼓*`、`S$英雄军鼓*` 把英雄状态和玩家状态隔开。

### 2. 回调要挂全生命周期
英雄装备系统至少要考虑：
- `@HeroTakeOnEx`
- `@HeroTakeOffEx`
- `@HeroDie`
- `@HeroLogin`
- `@HeroStruckDamage`
- `@HeroAttackDamage`

只挂穿戴不够，卸下、死亡、登录、受击、攻击都要有出口。

### 3. 条件命令和动作命令别放错区
`GetStringPosEX` 这类命令必须放在 `#IF`，不能塞进 `#ACT`。  
正确姿势是：先判定，再 `ExtractStringEx` 拆字段。

### 4. 3 秒限时属性要靠周期续期
`H.ChangeHumAbility ... 3` 不是永久值，是时效值。  
所以只做一次刷新会回落，必须配一个独立 timer 持续重写。

### 5. 引擎锁不要长持有
`LockUpdateAbil` 在这个工程里有实际副作用，尤其对月灵移动不友好。  
经验上，能不用就不用；必须用时也要尽量短，且立刻 `UpdateAbil` 收口。

### 6. 攻防分支要按主体精确分流
英雄攻击、英雄受击、目标是玩家还是怪，都要分开判断。  
这次的关键门禁就是：
- 英雄自身：`H.ChangeDamageValue`
- 英雄目标：`H.M.HumanHP`
- 目标是否玩家：`H.CHECKCURRTARGETRACE`

### 7. 变更最好分阶段落地
这个项目最后是按阶段补齐的：
- 阶段1：常驻属性
- 阶段2：受击减伤
- 阶段2补强：攻击向镜像
- 后续：图标、隐藏属性、更多方向效果

这样每一阶段都能静态回归，问题也更容易定位。

## 一句话结论

这次改动沉淀出的核心原则是：**英雄特性不要当单次加成写，要当一条完整生命周期链来写；状态隔离、回调闭环、定时续期、条件与动作分区，缺一不可。**
