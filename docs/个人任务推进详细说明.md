# 个人任务推进详细说明

本文只整理**个人 NPC 任务线**，不包含 `G0` 世界开放阶段、全服开图逻辑，也不展开地图自动开放设计。

## 1. 任务系统的基本形态

这套版本的个人任务不是单独的“任务引擎”，而是分散在 `Market_def/`、`Npc_def/`、`QuestDiary/` 里的对话脚本、击杀触发、奖励回写共同组成。

常见结构是：

- NPC 对话里负责接任务、交任务、发奖励
- `QMission-0.txt` 负责任务目录和任务说明页
- `QManage.txt` 和 `QFunction-0.txt` 负责任务按钮、入口触发
- `QuestDiary/系统功能/老登辅助/杀怪触发.txt` 负责击杀回写

任务通常围绕这些状态写法展开：

- `[n]`：个人任务标志位
- `U31` / `U32`：击杀计数
- `J1`：每日任务次数
- `CREDITPOINT`：声望奖励
- `GIVEFENGHAO`：称号奖励
- `GIVESTATEITEM`：绑定或状态道具奖励

## 2. 任务推进的通用规则

个人任务大多遵循下面的节奏：

1. 先用等级、背包空位、背包物品、元宝等条件做门槛。
2. 接任务时设置一个状态位，例如 `SET [8] 1`。
3. 击杀或收集阶段在击杀触发里累积计数，例如 `INC U31 1`。
4. 交任务时清理旧状态、写入完成状态、发奖励、刷新任务页。

常见判定包括：

- `CHECKLEVEL`
- `CHECKITEM`
- `CHECKBAGSIZE`
- `CHECKGAMEGOLD`
- `CHECKTEXTLIST`
- `CHECKMAPNAME`

## 4. 尸王殿任务：最清晰的击杀型任务链

来源：

- [Market_def/盟重城/书店-0161.txt](D:/wangsiProject/老登四合一GitHub/Mir200/Envir/Market_def/盟重城/书店-0161.txt)

这是一个很标准的三段式：

1. 对话接任务
2. 去尸王殿击杀尸王
3. 回来交任务

状态位：

- `[8]`：已接任务
- `[9]`：已完成击杀目标
- `[10]`：已交任务完成

击杀触发里有两层处理：

- 尸王被杀后把 `[9]` 置位
- 任务完成后由书店老板清理 `[8]`、写入 `[10]`，发声望和经验

这条线的好处是结构非常清楚，适合作为版本中“任务推进”的样板。

## 8. 个人任务推进的写法特点

这个版本的个人任务有几个很稳定的写法习惯：

- 一个任务尽量用一组连续状态位管理，不混用别的系统状态。
- 击杀任务会把“接取”和“完成”拆开写，避免直接跳结算。
- 大多数任务完成后都会 `RefreshMissPage`，让任务页回到可读状态。
- 奖励常常不止一种，通常是经验 + 声望 + 金币 + 道具 + 称号的组合。
- 任务说明文案和真实脚本大体一致，但以脚本状态位为准。

## 9. 静态阅读时要特别注意的点

1. `QMission-0.txt` 只是任务目录，不等于完整实现。
2. 任务状态位要和 NPC 脚本里的 `CHECK` / `SET` 配对看。
3. 击杀型任务要同时看 `Market_def` 和 `QuestDiary/系统功能/老登辅助/杀怪触发.txt`。
4. 一些任务在说明页里能看到，但当前脚本没有完全展开时，不能只凭文案下结论。
5. 如果任务涉及地图推进、传送或入口限制，要再结合 `MapInfo.txt` 和地图限制脚本看完整链路。
