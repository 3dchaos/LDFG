# 英雄军鼓「攻/防/血生效后约2秒回归」修复说明

- 状态：已修复（本地仓库已落地）
- 适用：翎风引擎（LD/Mir200）英雄军鼓（14号位独立穿戴）常驻属性持续性问题
- 日期：2026-09-03

## 现象

英雄面板攻/防/血随军鼓**生效**，但约 **2 秒后完全回归**未穿军鼓的数值。
测试现场关键点：**玩家本体不带军鼓，只有英雄穿 14 号位军鼓**。

## 根因（两层）

### 1. 属性是 3 秒限时，却没有续期
`H.ChangeHumAbility 属性 = 值 3` 的第 4 参数是**时间秒**（知识库 340 章：`ChangeHumAbility 属性 操作符 效果 时间秒(1-65535)`），即施加的是**3 秒限时属性**。引擎会按自身周期（约每 2 秒）重算英雄面板，把这类临时加成冲掉，因此**必须靠周期续期重施**才能持续。

玩家侧军鼓靠穿戴时 `SetOnTimer 87 2` 每 2 秒续期；而英雄军鼓穿戴（`@HeroTakeOnEx`）**只调刷新、没有启动任何专属定时器**，续期完全寄生于"玩家是否带军鼓 / 玩家登录 87 是否在跑"。玩家不带军鼓时 87 不跑 → 无续期 → 3 秒限时属性在约 2 秒后被引擎重算覆盖 = 回归。

### 2. 玩家作用域用 H. 探测英雄装备不可靠
原 `@英雄军鼓_定时检查` 在玩家作用域用 `H.CHECKUSEITEM 14` / `H.GetItemFieldValue 14 name` 探测英雄 14 位装备；全知识库 + `001-翎风引擎历史更新记录.md` 中**没有这两个 H. 版命令**（历史有 `H.CHECKLEVELEX`/`H.CHECKFENGHAO`/`H.CHECK` 等，独无 `H.CHECKUSEITEM`/`H.GetItemFieldValue`）。这类探测应在英雄作用域回调（`@HeroTakeOnEx`/`@HeroLogin`/`@HeroStruckDamage`）里做，不适合放进玩家作用域的周期定时器。

## 修复方案：英雄军鼓独立续期定时器 89

复用玩家侧已验证的"限时属性 + 周期续期"机制，且**完全独立**于玩家军鼓 / 87：

| 动作 | 文件 | 改动 |
|---|---|---|
| 穿戴/登录成功应用后启动 | `军鼓BUFF.txt @英雄军鼓_刷新` 末尾 | `SetOnTimer 89 2` |
| 卸下/失效时关闭 | `军鼓BUFF.txt @英雄军鼓_清理` 收尾 | `SetOffTimer 89` |
| 周期触发续期 | `QManage.txt` | 新增 `[@OnTimer89]` → `#CALL @英雄军鼓_定时检查`（插在 `[@OnTimer88]` 前） |
| 续期逻辑去探测化 | `军鼓BUFF.txt @英雄军鼓_定时检查` | 重构：不再用 H.CHECKUSEITEM/H.GetItemFieldValue 探测装备，改为仅当缓存状态 `N$英雄军鼓有效==1` 时重施 `@英雄军鼓_应用常驻` + 刷攻速/施法速度；否则 `SetOffTimer 89` 自停。装备在位交由穿戴/卸下两个**英雄作用域事件**维护。 |

`QManage @OnTimer87` 里原有的英雄军鼓调用保留，作为双入口兜底（幂等重施，与 89 无冲突；玩家同时带军鼓时两个定时器都会续期，结果一致）。

89 号定时器为空闲（工程已占用 1-10、85-88），不与现有冲突。
