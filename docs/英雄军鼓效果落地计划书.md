# 英雄军鼓效果落地计划书

## 一、目标

解决"英雄佩戴军鼓不生效"的问题：让英雄在 14 号军鼓位独立穿戴军鼓后，能获得与玩家相同方向的军鼓流派效果。

**设计取向（已与需求方确认）：**

1. **英雄独立穿戴自己的军鼓**：英雄使用独立装备栏的 14 号位，穿一件自己的军鼓（复用现有 54 件 StdMode65 物品，不新增物品、不改配置表）。
2. **复用玩家方向数值**：英雄与玩家穿同一名称、同一品质军鼓时，获得完全一致的基础属性、触发几率和方向效果。
3. **现有英雄攻速补偿并入新链路**：`@HeroLogin` 里那段给战士英雄固定攻速 `3` 的临时补偿，改为按英雄当前军鼓的追风流贡献统一结算；未穿追风流军鼓时归零，不再作为独立的"无军鼓默认平衡值"散落在外。

本计划只做静态设计与修改边界约定，不编译、不启动服务端。最终效果以运行脚本与本地手册为依据。

主脚本集中在：

- `QuestDiary/系统功能/军鼓流派配置.txt`：54 件军鼓按物品名称精确映射（`Name|Job|Direction|Quality|Stage|ConflictGroup|ModuleKey`）。
- `QuestDiary/系统功能/军鼓流派/战士军鼓.txt / 法师军鼓.txt / 道士军鼓.txt`：各方向品质基础 + 刷新/开启/关闭/攻击/受击/宝宝逻辑。

**数值与命令特征（重构后最新运行脚本）：**

- 品质基础集中在 `[@军鼓*_品质基础]`，一次性写入 `N$军鼓点/大点/血蓝/吸血/攻速/破防/准确/触发几率/切割/减伤` 等方向数值桶。
- 常驻属性以 3 秒短窗口下发（`ChangeHumAbility ... 3`、`AddHumNewValue ... 3`、`ChangeState 10 3 100` 吸血、`ChangeSpeed 2/3`），由 2 秒定时器持续续期覆盖。
- 攻击/受击触发已**不依赖具体技能名判断**，统一为：目标非玩家（`NOT CHECKCURRTARGETRACE = 0`）+ 概率门（`RANDOMEX <$STR(N$军鼓触发几率)> 100`）→ 怪物目标切割（`M.HumanHP - ...`）或受击减伤（`ChangeDamageValue 1 - ...`）。
- 法师/道士方向还有层数、范围状态、`RangeHarm`（只影响怪物）、养娃人宝宝联动等第二层效果。

### 2.2 英雄侧缺口（问题根因）

英雄侧当前**完全没有军鼓生命周期**：

1. `QFunction-0.txt` 没有任何英雄穿戴 / 攻击 / 受击 / 死亡的回调接入（连 `@HeroTakeOnEx`、`@HeroTakeOffEx`、`@HeroAttackDamage`、`@HeroStruckDamage`、`@HeroDie` 标签都不存在）。
2. `军鼓BUFF.txt` 通篇用无前缀命令操作"当前主体（玩家）"，只在 `[@Login]` 与 `[@HeroLogin]` 各调了一次。唯一带英雄前缀的 `[@军鼓BUFF_刷新战士英雄攻速]` 只是给战士英雄一个**固定基础攻速 3**，与玩家军鼓无关。
3. 玩家定时器 87 与登录刷新只处理玩家主体，英雄的 3 秒短窗口没有续期来源，即使穿戴了军鼓也无法维持。
4. 英雄独立装备栏的 14 号位从未被读取，因此英雄穿军鼓后系统认为"没有军鼓状态"，什么都不结算。

**结论：英雄穿军鼓不生效，不是物品库或配置表问题，而是英雄侧没有接入任何军鼓触发/刷新/清理生命周期。**

## 四、落地总体方案

在不推翻玩家侧结构、不改 54 件物品与配置表的前提下，给军鼓增加一套**"英雄主体"镜像生命周期**，复用玩家侧的方向模块数值。

### 4.1 核心思路

把 `军鼓BUFF.txt` 从"只服务玩家主体"扩展为"服务玩家 + 服务英雄"双主体。玩家侧命令（无前缀）保留；英雄侧用 `H.` 前缀命令，读取英雄 14 号位、按英雄职业与方向分发、维持英雄 3 秒短窗口。

两条主体各自维护一套状态变量。为避免变量名互相污染，英雄侧状态建议使用独立的 `S$英雄军鼓*` / `N$英雄军鼓*` 变量名，或沿用 `H.` 前缀变量域。

### 4.2 英雄侧生命周期接入点

| 英雄事件 | 新标签（放入 `QFunction-0.txt`） | 动作 |
| --- | --- | --- |
| 穿戴 | `[@HeroTakeOnEx]`，判断 `<$H.CurItemPos>` = 14 | `#CALL 军鼓BUFF.txt @英雄军鼓_刷新` |
| 卸下 | `[@HeroTakeOffEx]`，判断 `<$H.CurItemPos>` = 14 | `#CALL 军鼓BUFF.txt @英雄军鼓_清理` |
| 攻击掉血前 | `[@HeroAttackDamage]` | `#CALL 军鼓BUFF.txt @英雄军鼓_攻击掉血前` |
| 被攻击掉血前 | `[@HeroStruckDamage]` | `#CALL 军鼓BUFF.txt @英雄军鼓_被打掉血前` |
| 死亡 | `[@HeroDie]` | `#CALL 军鼓BUFF.txt @英雄军鼓_死亡检查` |

| 定时/登录 | 新标签（放入 `QManage.txt`） | 动作 |
| --- | --- | --- |
| 定时续期 | 在 `[@OnTimer87]` 内追加 | 若英雄在线 → `#CALL @英雄军鼓_定时检查`（对英雄 `H.` 续期 3 秒窗口） |
| 英雄上线 | `[@HeroLogin]` 内追加 | `#CALL @英雄军鼓_刷新`（替代现有固定攻速补偿） |

> 说明：英雄登录/定时由"主人"环境执行，因此对英雄的操作必须显式加 `H.` 前缀（参考 `709-英雄上线触发.md`）。英雄上线刷新要放在 `CheckHeroOnline`/确定英雄存在的分支内。

### 4.3 英雄军鼓主脚本新增段（建议放在 `军鼓BUFF.txt` 内，`英雄军鼓` 独立标签段）

参考玩家侧 `军鼓BUFF.txt` 结构，新增一组 `@英雄军鼓_*` 标签：

- `@英雄军鼓_刷新`：英雄 14 号位穿戴确认 → 读取英雄军鼓名称 → 走 `军鼓流派配置.txt`（按名称匹配同一行，取方向/职业/品质/数值桶）→ 用 `CheckHeroJob` 校验英雄职业与物品职业一致 → 应用/切换英雄方向模块 → 刷新英雄图标与定时。
- `@英雄军鼓_战斗确认`：确认英雄 14 号位仍在、名称与缓存一致、英雄职业匹配。
- `@英雄军鼓_定时检查 / 定时续期`：英雄在线时按 `H.` 前缀对英雄重发 3 秒短窗口（基础属性、吸血、攻速/施法速度、方向隐藏属性）。
- `@英雄军鼓_图标刷新 / 图标说明`：给英雄挂自身方向 BUFF/顶戴图标（能否对英雄用 `SetArrBuff` 需前置验证，详见第七节；顶戴 `H.SETICON` 已确认可用）。
- `@英雄军鼓_清理`：停英雄定时段、清英雄图标/顶戴、关闭当前英雄方向模块、清空英雄状态变量、英雄攻速归零。
- `@英雄军鼓_攻击掉血前 / 被打掉血前`：战斗确认 → 按英雄当前方向 `#CALL` 方向模块，用 `H.ChangeDamageValue`/`M.HumanHP -`（怪物切割）结算，成功后打印反馈。

### 4.4 方向模块：英雄镜像

玩家侧三份 `战士军鼓.txt / 法师军鼓.txt / 道士军鼓.txt` 的方向逻辑，建议按"同文件内追加英雄版标签"或"独立 `英雄军鼓流派/` 目录"两种方式之一落地（实施前二选一，见第八节实施顺序第一步）。

英雄版方向标签复用玩家侧同一套品质数值桶（复用玩家方向数值），但把作用于主体的命令全部换成 `H.` 前缀：

| 玩家命令 | 英雄命令 | 用途 |
| --- | --- | --- |
| `ChangeHumAbility ...` | `H.ChangeHumAbility ...` | 基础攻防血 |
| `AddHumNewValue ...` | 需验证（见第七节）或按英雄可用等价命令 | 隐藏属性层 |
| `ChangeState 10 3 100 ...` | `H.ChangeState 10 ...`（验证） | 吸血 |
| `ChangeSpeed 2/3` | `H.CHANGESPEED 2/3` | 攻速 / 施法速度 |
| `ChangeDamageValue ...` | `H.ChangeDamageValue ...` | 伤害增减 |
| `M.HumanHP - ...`（怪物切割） | `M.HumanHP - ...`（目标仍是怪物，命令作用于目标，前缀用 `M.`） | 战士切割 |
| `RangeHarm`（只影响怪） | 验证英雄侧是否仍以英雄为释放者 | 法师满层 / 道士毒爆 |
| `RECALLMOB` / `CHECKSLAVECOUNT` / `KillCallMob` | `H.RECALLMOB` 等（验证） | 道士养娃人补宝宝 |

> 原则：作用于"当前主体自身"的命令加 `H.`；作用于"当前目标（怪物/敌人）"的命令仍用 `M.`；方向内同一套逻辑只换主体前缀，数值不动。

### 4.5 现有攻速补偿的收敛

删除 `@HeroLogin` 里散落的固定攻速 `3` 补偿，把战士英雄的基础/路线/最终攻速纳入新链路（对齐 skill 沉淀的"赋值型速度命令必须通过贡献变量汇总"规则）：

- `N$战士英雄基础攻速`、`N$战士英雄路线攻速`、`N$战士英雄最终攻速` 由 `@英雄军鼓_刷新战士攻速` 汇总，仅战士英雄且穿追风流（剁馅机）军鼓时路线贡献取 `N$军鼓攻速`，其余取 0。
- 仅执行一次 `H.CHANGESPEED 2 <最终值> 3`。英雄登录、军鼓同状态续期、切换方向、清理都必须调用同一汇总入口。
- 施法速度同理：法师英雄只在穿法师军鼓方向时走 `H.CHANGESPEED 3` 汇总。

## 六、关键限制与风险（落地前必须确认）

1. **英雄 14 号位能否实际穿戴 StdMode65**：这是前置可行性项。需确认英雄装备栏存在 14 号军鼓位、且英雄可穿戴玩家同款军鼓物品。若英雄装备栏没有军鼓位或不允许该类物品，需回退到"玩家穿军鼓同时增益英雄"备选方案（已在第一节以问题形式确认过归属，但穿戴可行性仍需实测）。
2. **英雄侧命令前缀可用性**：`H.ChangeHumAbility`、`H.CHANGESPEED`、`H.SETICON`、`H.ChangeDamageValue` 手册明确；`H.AddHumNewValue`、`H.CheckUseItem`、`H.GetItemFieldValue`、`H.SetArrBuff`/`H.CloseArrBuff`、`H.ChangeState` 手册未逐条写明，需在本地实际脚本验证。若 `H.AddHumNewValue` 不可用，方向隐藏属性层需改用英雄支持的等价方式或降级。
3. **英雄自身 BUFF 图标栏**：玩家军鼓用 `SetArrBuff 87`（玩家 BUFF 栏）。英雄是否有独立 BUFF 栏图标能力（`H.SetArrBuff`）未明说。若不可用，英雄方向可只做属性/顶戴表现（`H.SETICON` 已确认），自身状态图标降级。
4. **英雄宝宝掉血前触发**：玩家道士养娃人的"宝宝攻击掉血前"用的是 `@SlaveAttackDamage`；手册英雄宝宝侧只有 `@HeroSlaveAttack`（攻击发生触发，非掉血前修改）。英雄养娃人的"宝宝联动加码"可能无法在掉血前精确改伤，需验证或用攻击触发替换实现。
5. **短窗口维持依赖英雄在线**：英雄的 3 秒短窗口只能由主人定时器（`@OnTimer87`）在英雄在线时 `H.` 续期。英雄离线/召回状态必须跳过英雄续期，否则命令可能落空或报错。需显式判断英雄在线。
6. **变量域隔离**：英雄状态若复用玩家 `S$军鼓*`/`N$军鼓*` 会被互相覆盖。必须使用独立变量名域（如 `英雄军鼓` 前缀），或确认 `H.` 前缀下引擎提供了独立变量空间。
7. **目标类型（玩家 vs 怪物）**：切割类只对怪物生效（`NOT CHECKCURRTARGETRACE = 0` 表示目标非玩家，含英雄/怪物/分身）。英雄攻击的当前目标判断需用英雄变量（`<$H.CURRRTARGETNAME>` / `H.CHECKCURRTARGETRACE`），不能照抄玩家变量。
