## 英雄军鼓阶段1 实机 bug 修复（GetStringPosEX 条件命令落区）
- 用户实机复测报错：`GetStringPosEX ..\QuestDiary\系统功能\军鼓流派配置.txt <$STR(S$英雄军鼓名称)> N$英雄军鼓配置行 S$英雄军鼓配置文本 0` 脚本错误，行号落在运行副本 D:\MirServerLD12 的 QFunction/QManage #CALL 展开处（9973/3605/4455/4551），本机无该目录（用户在别机部署运行）。
- 根因（**翎风可复用语法经验**）：`GetStringPosEX` 是**条件命令**，必须写在 `#IF` 区作判断，不能放 `#ACT` 动作区。玩家侧 `军鼓流派配置.txt` 的 `@军鼓配置_读取` 即 `#IF GetStringPosEX ...` 结构。同类要注意：能返回 true/false 的检测类命令（CHECKUSEITEM/GetStringPosEX/CheckHeroOnline/CheckHeroJob/EQUAL/RANDOMEX/CHECKCURRTARGETRACE）都放 #IF；无返回值的动作命令（GetItemFieldValue/ExtractStringEx/ChangeHumAbility/MOV/#CALL）放 #ACT。误把条件命令当动作用是引擎"脚本错误"常见根因。
- 修复：`军鼓BUFF.txt` 英雄军鼓_刷新 内配置解析段改为与玩家侧同构（#IF GetStringPosEX → 空#ACT → EQUAL 配置行=0 判断未命中→清理），全落英雄独立变量域。工具：`tools/fix_hero_jungu_getstringpos.py`。已备份 `.workbuddy/backup-英雄军鼓-20260902/军鼓BUFF.txt.pre-fix-getstringpos.bak`。check_hero_jungu_stage1.py 重跑仍 0 失败。
